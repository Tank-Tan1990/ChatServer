# ChatServer 开发历程与双工具协作

> 说明：本文档按用户要求，**只保留最终确定版的设计结论**，不罗列中间反复修改的过程版本。重点呈现两个 AI 编程工具（QClaw、WorkBuddy）的协作边界，以及关键设计"从初稿收敛到定稿"的结果。

## 一、协作总览

ChatServer 由两阶段 AI 编程工具接力完成：

| 阶段 | 工具 | 时间 | 角色 | 核心交付 |
|---|---|---|---|---|
| 奠基期 | **QClaw**（OpenClaw 内核 v0.2.35） | 2026-04 | 从 0 到 1 | 全模块功能、REST/WS 骨架、JWT 双 Token、多库抽象层、部署蓝图、10K 压测方法论与测试脚本 |
| 定稿期 | **WorkBuddy**（腾讯 AI 助手） | 2026-09 ～ 10 | 从能用到达标 | 连接池配置化（800）、Argon2id 可调、消息异步批量写入、WS 推送修复、10K 全链路验证（注册+登录+消息 100%） |
| 贯穿 | 共享 | — | 工程资产 | Rust 源码（`src/`）、文档（`docs/`）、压测脚本（`tests/`） |

两工具并非替代关系，而是**接力**：QClaw 搭建了功能骨架与架构构想，但 10K 并发目标在其末期仍反复失败（连接池/参数失控、写路径缺陷）；WorkBuddy 以"10K 100% 成功"为靶心，完成了性能定稿与缺陷修复，使目标最终落地。

## 二、关键设计的最终收敛（仅列定稿结论）

> 以下设计在 QClaw 阶段曾多轮摇摆，WorkBuddy 阶段收敛为最终确定版。此处不展示中间版本，只说明"最终确定为什么"。

| 设计项 | 最终确定版 | 收敛说明 |
|---|---|---|
| 数据库驱动 | `sqlx::AnyPool`（多库抽象层保留） | 多库抽象构想保留；实际查询以手工 `try_get`/类型转换走 MySQL，其余库类型仅停留在迁移脚本，未经验证 |
| 连接池规模 | 读 300 / 写 500 / 总上限 800（按 `max_connections` 80% 配置） | 由硬编码上限改为配置驱动并自动缩放，杜绝历史超卖与参数失控 |
| 密码哈希 | Argon2id，默认低强度档（`m=7MiB,t=1,p=1`），`ARGON2_MODE=secure` 切高强度；旧 SHA256/bcrypt 首次登录透明迁移 | 取代早期 bcrypt/SHA256 的来回方案，兼顾安全与性能，旧数据无损 |
| 消息写入 | Snowflake 预生成 ID + `MESSAGE_ASYNC=1` 异步批量落库（3 worker，50ms/500 条事务批量） | 规避线上 `messages.id` 无自增约束，并把 N 次 fsync 压缩为 1 次，是消息吞吐达标关键 |
| WebSocket 推送 | `uid → {conn_id → Sender}` 多端在线 + 统一 `push_to_user/group` | 修复 WS 发送路径因 `id` 无自增导致的写入失败，REST 与 WS 共用推送链路 |
| 登录鉴权 | 密码校验 `spawn_blocking` + 信号量（300）+ 后台异步更新状态 | 隔离 CPU 密集型 Argon2id 校验，避免阻塞 Tokio worker |
| 限流 | Redis 滑动窗口 + 内存兜底，`RATE_LIMIT_RPM` 可覆盖 | 默认关闭，压测/生产按需放开 |

## 三、两工具贡献边界（一览）

### QClaw 奠基（2026-04）
- 完整的 7 大功能模块 CRUD 与 REST API 骨架（注册/登录/好友/消息/群组/搜索）。
- JWT 双 Token 认证体系与 Token 黑名单思路。
- WebSocket 实时消息 + 30s 心跳 + Redis 在线状态（TTL 5 分钟）的实时通信基础。
- 多数据库抽象层（`DatabaseType` / `SqlDialect` / `DbPool`）的架构构想。
- 读写分离连接池 + 写信号量 + 后台写队列的架构尝试。
- 部署蓝图（Docker / Compose / Nginx 负载均衡）与完整的 10K 压测 Python 脚本体系。

### WorkBuddy 定稿（2026-09 ～ 10）
- 连接池配置化与按 `max_connections` 80% 自动缩放（根治连接耗尽）。
- Argon2id 可调档密码哈希 + 旧哈希透明迁移。
- 消息异步批量写入（Snowflake + 后台 worker），削平 MySQL fsync 峰值。
- WS 单聊/群聊推送修复（Snowflake ID 预生成），打通端到端实时链路。
- 10K 全链路压测验证：注册 + 登录 + 发消息 500/1000/2000/5000/8000/10000 并发 **100% 成功**，零连接泄漏。
- 目录治理：`.py`/`.ps1` → `tests/`，`.md` → `docs/`，产物 → `target/`，并清理压测数据。
